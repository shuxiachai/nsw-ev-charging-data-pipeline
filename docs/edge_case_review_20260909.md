## 尚未被代码修复消除的评分风险

- **Cleaning /20：**仍有未解决的地点地址/坐标冲突。它们留在原始记录和覆盖分母中，排除出分析就绪视图；这属于明确处理不确定性，但不能因此声称已核实全部站点的现实 SA4。B01 撤回的 Wagga Wagga 源行 727 加入待核实列表，需要能解释 `8/24` 与 `8` 地址关系的正式资料。
- **Acquisition /10：**官方 December 文件名与 April 2026 元数据日期冲突尚需课程方解释。自动取得官方文件已实现，历史版本语义尚未得到确认。
- **Augmentation /20：**约 50% 覆盖只是最高档的一部分，还要求正确的新属性、自动方式、方法与实例、无明显系统性错误。不能用运营商联系方式覆盖率代替站点级覆盖，不能将同源坐标修正后的零距离当独立准确率。
- **Storage /20：**报告必须解释 location/charger_record 粒度、来源及审计关系、约束与规范化选择。已经有 DDL 和数据库，不代表报告中的设计论证可以省略。
- **Report /15：**目前 Word 是模板，正式项目报告尚未完成。正文页数、schema 图、推荐章节、真实成员贡献、AI 使用报告仍须在最后提交前完成。
- **Organisation /15：**README 的命令、数据版本、结果数字必须对应最终 ZIP；改完代码后只提交旧数据库或旧包会留下明显不一致。已保留固定依赖、复现脚本及失败路径测试；其他操作系统尚未实际运行验证。

不能根据上述风险直接相加猜测分数。当前优先级应是身份/位置正确性和可复现提交，其后完成报告里的方法证据和设计解释。

## 不属于 bug 的保守处理

无法核实的位置不强行修正、模糊/复用候选拒绝自动接受、没有数值功率就保留 NULL、把单独标记的海岸近似与精确包含区分、将 JOLT 站码作为有效新增属性，都是可以保留的做法。不要为提高覆盖率而放宽证据标准，也不需要为作业规模引入新框架或分布式架构。

## 验证范围

复现用例在内存数据库或 assignment/.review 的隔离文件中构造；原有 raw 文件没有改写。生产修复需要完整重建、功能与异常路径测试、数据库内容/结构/确定性输出的离线对比，最后生成并检查提交包。最终测试数量、覆盖率和检查结果见 README 及 outputs 下的生成证据。
