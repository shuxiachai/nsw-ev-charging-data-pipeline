### 匹配准确性仍有实际边界

已达到约 50% 站点级新增属性覆盖的目标，也提供所有候选、拒绝原因和弱匹配样本；这不等于测得 100% precision。近距离且同运营商的匹配允许外部地址缺失；多入口、大停车场、历史 pin 偏移仍可能造成不确定性。四条新修正使用 OSM 坐标，其后对同一 OSM 对象的零距离匹配属于依赖证据，不能作为独立精度验证。

**剩余有价值的工作：**报告使用可追溯的成功、拒绝、歧义实例解释方法；对当前弱匹配样本增加官方站点证据会提高可信度。如果要声称 precision/recall 数值，必须先建立独立标注样本及明确抽样方法，不能由距离或现有匹配分数推导“准确率”。Cowra 的连接器来源分歧仍保留两种观察，不擅自决定哪个来源是真值。

### 代码包完成不等于作业全部完成

正式项目报告 PDF、真实组员身份和贡献说明、AI 使用报告仍是独立交付物。目录中的 Word 文件是模板，不能作为已完成 report。后续报告应按模板覆盖数据取得、质量处理、空间整合、增强实例、数据库关系图与设计理由、挑战和限制；正文最多六页，身份与总计不超过 100 词的贡献说明需由小组核实。此轮专注代码及技术证据，尚未代写该报告。

## 可选的后续改善

- 有新权威资料时逐条减少九个未解决地点，或者补强弱匹配样本；每次更新证据、配置和验证，不直接手改派生 CSV/数据库。
- 对目标评分环境增加 Linux/macOS 运行验证。目前真实验证环境是 Windows/Python 3.12；提供其他平台命令不等于已经测试过。
- 若后续扩大数据规模，再考虑分块、增量存储或更细日志；当前批处理规模不需要先重构。
- 报告阶段将已有 Mermaid schema 渲染为清晰图，并选择少量质量统计图。图表排版改善不要求改动当前数据库结构。

## 复现与提交核对

从解压后的项目根目录按 README 安装依赖，运行 `python -m ev_pipeline all`，再运行 `python scripts/verify_project.py`。验证包括功能/异常路径测试、离线重建的全部逻辑表及 CSV 一致性、实际数据库 SQL 检查。最后运行 `python scripts/package_submission.py`，产生经过校验的代码与数据库 ZIP。

运行成功记录只适用于记录的指纹和输出；代码、输入或结果改变后必须重新验证。原始快照不可被“重新下载”静默更新。已经安装的空间扩展是离线重建前提，跨平台首次安装仍需联网。
